## What this project is

A Clang frontend plugin (`libScIntAssignChecker.so`) that warns when a C++ builtin-type variable (`int`, `long`, `double`, etc.) is assigned to a SystemC `sc_int<W>` or `sc_uint<W>` type. It is loaded into `clang++` at compile time — not linked as a library.

## Build

```bash
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=RelWithDebInfo   # RelWithDebInfo for debugging
make -j$(nproc)
```

Output: `build/libScIntAssignChecker.so`

**Critical CMake constraint:** The plugin must NOT link against Clang/LLVM libraries. The `.so` is loaded into an already-running `clang++` process that owns those symbols — duplicate linkage causes crashes (duplicate command-line option registration).

## Running the plugin manually

```bash
clang++ -fsyntax-only \
    -Xclang -load -Xclang build/libScIntAssignChecker.so \
    -Xclang -add-plugin -Xclang sc-int-assign-checker \
    -I$SYSTEMC_HOME/include -std=c++17 your_file.cpp
```

## Code architecture

All plugin logic lives in two files:

- `src/BuiltinToScIntChecker.h` — declares `ScIntAssignVisitor`, `ScIntAssignConsumer`, `ScIntAssignAction`
- `src/BuiltinToScIntChecker.cpp` — implements them and registers the plugin

**Class hierarchy:**
1. `ScIntAssignAction` (`PluginASTAction`) — entry point registered under the name `sc-int-assign-checker`. Creates the consumer.
2. `ScIntAssignConsumer` (`ASTConsumer`) — receives the completed AST and drives the visitor over it via `TraverseAST`.
3. `ScIntAssignVisitor` (`RecursiveASTVisitor`) — the core logic. Visits every `CXXOperatorCallExpr` and emits a warning when:
   - the operator is an assignment (`=`, `+=`, etc.)
   - the callee method's class is/derives from `sc_dt::sc_int_base` or `sc_dt::sc_uint_base` (checked recursively through base classes)
   - the RHS (after stripping implicit casts) is a `DeclRefExpr` with a builtin type
   - the call site is not inside a system header
